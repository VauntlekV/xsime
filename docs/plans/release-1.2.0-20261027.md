## 发布顺序

1. 提交并推送官方插件，锁定本体引用；本体和插件均保留原始作者。
2. 完成逐端对齐，在集成 PR 上运行远端检查，修复失败后合并 main。
3. 冻结同一 main 提交与插件 pin，构建四端正式包及社区 IPA。
4. 沿用已授权的签名、Android 长期密钥和 Apple 账号；发布前验证实际凭据和权限。
5. iOS 归档上传后分别读回处理、TestFlight 分发和 App Review 状态。GitHub 发布和商店生效分别记录，保留当前可用地区及审核通过后的自动发布设置。
6. 匿名读回公开资产、校验和及更新清单，再记录最终结果。

## iOS 上架协作

维护者明确授权在构建完成后协调 [Publish-appstore](codex://threads/01a0e122-f4e2-7ec2-a923-f323d862a17f)；交接冻结提交、构建号、归档来源、SHA-256 和远端检查结果，再由该对话继续 TF 与商店。构建未完成前不报告已提交上架。

已发现并备份主工作区中唯一与插件源不同的生成文件 `platforms/ios/Support/BufferPlugins.swift`，将其中的助手实现补回官方插件源码，避免干净 CI 构建丢失工作副本能力。

官方插件 PR #22 已以保留原提交的方式合并到 main（3566548）；本体继续锁定已经通过全部五项原生集成检查的插件提交 8709e06。原工作区中的生成文件与备份摘要一致，补回的插件源码也与该文件一致。Linux 最后的候选矩阵用例补齐显式焦点，普通输入回归提前执行；五份 README 的下载入口同步锚定 1.2.0，iOS 商店可用状态以 Apple 为准。

最终集成修复了 Mailbox 无锁快照读取与原子替换相遇时的链接计数竞态。读取允许已打开、权限仍为 0600 且属于本用户的零链接快照，写入、删除和锁仍要求单链接；并发完整快照回归与最终 Linux CI 均通过。五端主线检查及正式发布流水线全部成功，公开版本为 1.2.0。Apple 已处理构建 67，外部 TestFlight 为 `WAITING_FOR_BETA_REVIEW`，App Review 为 `WAITING_FOR_REVIEW`，商店按审核通过后自动发布设置等待生效。

原开发工作区及其 26 项未跟踪资料保持原样，原始 iOS 生成文件已与备份及补回的官方插件源码核对。两仓远端仅保留 main；删除旧分支前的引用已保存在本地备份中。正式标签保持冻结，后续交付文档提交不改变安装包源码。
